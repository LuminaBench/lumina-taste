Quickstart

Working before your coffee is cold

  1. Run the setup. It finds your framework, adds the SDK and writes a config file you can read.
  2. Send one event. The command line shows it arrive, with the time it took.
  3. Query it. SQL in the console, or the same query over the API.

The SDK

One call. It never blocks your request.

Events are batched in memory and sent in the background. If Halyard is down, they wait on disk and your code carries on.

What you stop building

The parts of an event pipeline nobody wants to own

  • Typed from your schema

    Declare an event once. The SDK gives you types for it in Node, Python and Go.

  • Replay the last 30 days

    Shipped a bug in a consumer? Fix it, then send the same events through again.

  • Queryable in under a second

    Median time from your call to a row you can select: 640 ms.

  • Bad events stop at the door

    Events that break their schema are held, shown to you and never mixed in.

  • Keys that do one thing

    Write-only keys for servers and browsers, read keys for dashboards, each with a limit.

  • Stored where you choose

    EU or US, chosen per project and written into the contract.
